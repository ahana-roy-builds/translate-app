# Speak Duet implementation plan for continuous translation

**Start with the speech delivered to the translator.** All 174 clean-text translations preserved the intended meaning on the iPhone 13 Pro. Only 118 of the same 174 turns did so from speech. In 46 of the 56 failures, the phone correctly transcribed the identical recording with the source language selected. Those 46 turns give us a measurable first target. The other ten also failed the fixed-language control. [Device report](all-language-iphone-report-2026-11-19.md) · [Per-turn evidence](all-language-iphone-evidence-2026-11-19.json)

## 1. Make the failures reproducible

- Promote the synthetic recording manifest, exact WAVs or byte-verified copies, and the temporary device runner into a repeatable test fixture. Keep the event sequence, partner language, silence, and which speaker went first. The English ticket recording succeeded in four fresh sessions but failed in several ongoing conversations. A test that starts fresh for every sentence will miss this bug.
- Add fixture-only diagnostics for each turn’s sequence, detected start and end, delivered audio range, both modules’ final progress, both transcripts before and after clipping, selection reasons, stored participant, replay locale and timing. Record pause-to-first-visible-translation separately from time spent waiting for a user. Keep audio and transcript traces confined to test fixtures.
- Use simulators for deterministic policy, queue and presentation tests. Use the physical iPhone for Apple recognition, translation, synthesis and latency. Reproduce the baseline with Auto Speak off, then repeat with it on. Save the current working-tree revision and the model/OS versions alongside each run. [Recognition tests](../ios/Tests/ContinuousSpeechRecognitionPolicyTests.swift) · [Coordinator and playback tests](../ios/Tests/ContinuousModePolicyTests.swift)

## 2. Recover complete turns without slowing every pause

The shared recognizer assigns a word to a turn by where its timestamp ends. It can also accept one available candidate after waiting 500 ms for the other module. When the Spanish result lost “puente,” the alternate still contained it. Asking for an extra 320 ms lost the word in both trials. The evidence supports testing clipping, final-result timing and shared analyzer state independently. [Word clipping and accumulation](../ios/Sources/Domain/ContinuousSpeechRecognition.swift) · [Finalization and result deadlines](../ios/Sources/Services/Local/AppleContinuousSpeechRecognizer.swift)

1. Run three paths on identical, ordered audio. **A** is the current implementation. **B** changes only ownership of a timed word spanning a turn boundary. Assign it once to the turn containing the larger overlap, with a deterministic tie rule. **C** collects finals from an analyzer fed only that turn’s audio. Compare pre-clipping and post-clipping words for A and B, then compare B and C. Evaluate the normal pause, maximum-duration split and a reply that starts while the prior turn is finishing.
2. For C, reuse the existing PCM slicing, pre-roll, previous-turn boundary and queued finalization in the English–Hindi implementation. Generalize its audio handling separately from its Hindi-specific language evidence. Exercise the Apple module configuration actually used by each candidate path in readiness checks. Use the existing live draft path where measurements justify its cost. [Turn-local audio and analyzer](../ios/Sources/Services/Local/TurnSpeechSession.swift) · [Module configuration](../ios/Sources/Services/Local/AppleSpeechModulePlan.swift)
3. Prefer B if it recovers the failing words reliably. If C adds meaningful recoveries, measure it first as a selective second pass when a recognizer is late, boundary words are ambiguous, or speaker evidence conflicts. Measure always-on C separately to detect failures a selective trigger misses. Choose the least expensive path that meets the quality gates. Do not splice words from the other language’s transcript.
4. Capture can continue while one bounded final-recognition job runs. Respect the coordinator’s queue limit, release transient audio after resolution, and cancel stale results by session generation on interruption or pair change. Commit and translate once per sequence. A timeout must leave the following turn usable. [Conversation queue and lifecycle](../ios/Sources/Services/ContinuousConversationCoordinator.swift)

## 3. Resolve the speaker before speaking the translation

All six wrong assignments had a review flag. Another 65 correctly routed turns had the same flag. Three of the six wrong assignments had no alternate transcript, one alternate contained only punctuation, and two contained little beyond the amount. The existing Swap Language action requires an alternate. Blocking every review flag would interrupt many conversations and swapping the stored strings would fail on these very examples. [Decision policy](../ios/Sources/Domain/ContinuousSpeechRecognition.swift) · [Correction flow](../ios/Sources/Services/ContinuousConversationCoordinator.swift)

- Track a specific unresolved-speaker reason separately from ordinary short-utterance, low-confidence and Hindi Beta review. Discard punctuation-only finals for all pairs. Treat amounts, names, short replies and shared words as weak language evidence. Compare the two candidates’ acoustic evidence and, for sufficiently informative text, whether the words fit the recognizer’s claimed language. Calibrate on held-out recordings, including related languages and Hinglish.
- For a strong conflict, try the bounded second pass before committing a direction. If it remains ambiguous, show the transcript with an inline choice of the two languages and keep listening. The choice resolves that turn only. A usable alternate goes through the existing correction transaction. With a missing or unusable alternate, decode transient audio once with the selected locale while available, or offer repeat/edit after it expires. Only a resolved source can trigger automatic speech.
- Use the same turn ID and sequence for correction. Update the transcript, speaker, both locales, translation, warnings, history and both Relay panels together. A retry or stale correction must never play the prior text. Read older history with compatible defaults for any new review field. [Saved turn format](../ios/Sources/Domain/Models.swift) · [Talk turn controls](../ios/Sources/UI/ContinuousConversationView.swift)

## 4. Repair number checks and replay in parallel

The checker gave identical mismatch decisions to the correct and corrupted versions in every direction tested. It also blocked nine correct replays. All 76 completed replays synthesized exactly the saved target and text. Fix the decision about whether and what to play before changing the synthesizer. [Entity comparison](../ios/Sources/Domain/EntityIntegrity.swift) · [Automatic speech policy](../ios/Sources/Domain/ContinuousConversation.swift)

- Extend the locale-aware extractor to represent a quantity with its unit or currency, and a time with its action and whether it is affirmed or negated. Reuse existing normalization for digits and dates. Cover number words, currency on either side, Japanese counters, Korean number forms and Hindi digits. Compare “departs at nine / excludes ten” across word orders. A missing relationship should remain uncertain. Preserve existing checks for other entity types and their behavior in manual mode.
- Have the coordinator and both playback controls consume the same decision. A confirmed mismatch blocks automatic speech and replay. A corrected turn is rechecked. A verified equivalent price can be replayed. Preserve Hindi Beta’s existing explicit playback for important details and distinguish an unresolved speaker from a verified mismatch in the UI. Test both panels, repeated taps and interrupt/resume. [Coordinator](../ios/Sources/Services/ContinuousConversationCoordinator.swift) · [Beta playback behavior](../docs/private-beta-app-store-connect.md) · [Entity regression tests](../ios/Tests/EntityIntegrityTests.swift)

## 5. Evaluate a better offline Hindi model separately

Run a development-only paired trial on the iPhone 13 Pro. Feed the same bounded turn audio to Apple and multilingual Whisper large-v3-turbo Q5, specifying Hindi only after the speaker is reliably identified or explicitly chosen. Send each transcript through the same Apple translator. Keep English controls and collect natural Hindi and Hinglish from consenting speakers, including short replies, names, prices, dates and noise. Have bilingual reviewers score the final messages blind.

On the original 13 Hindi recordings, the Mac Whisper trial improved full meaning from 8/13 to 10/13, recovered two time errors and a location, and introduced a Delhi place-name error. The model is 574 MB. Measure cold load, warm pause-to-result latency, peak memory, energy, thermal behavior and immediate English replies on the phone. Advance to an optional Hindi model download only if held-out meaning improves without a rise in critical-detail errors and the device meets the latency budget. Retain the Apple path when the model is absent, times out or is disabled. [Matched results](all-language-iphone-report-2026-11-19.md) · [Model file and checksum](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-large-v3-turbo-q5_0.bin)

## Verification and rollout

| Check | Proposed acceptance for this fix |
| --- | --- |
| Automatic turns | On three runs of the 174-turn sequence, each pause yields one result or an explicit review. Zero missing, duplicated or cross-contaminated turns. Count unresolved reviews separately from correct automatic results. |
| Meaning | Recover at least 23 of the 46 failed turns with a successful fixed-language control. Target at least 141/174 correct automatic translations per run, preserving the baseline successes. Inspect every regression by pair. Keep clean-text controls at 174/174. |
| Speaker and voice | Each of the six known routing failures resolves correctly or requests a choice before audio. Zero wrong-language automatic playbacks or replays. Track prompts on the 168 previously correct turns so a build cannot pass by deferring every decision. |
| Important details | All 58 correct prices and 58 correct departures pass the mismatch check. All 58 changed prices and 58 reversed departures trigger it. Restore all nine correct blocked replays. Include equivalents and counterexamples with new values and reversed clause order. |
| Responsiveness | Benchmark warm short turns against the repo’s endpoint-to-visible targets of p50 ≤ 1.5 seconds and p95 ≤ 3 seconds. Also measure draft latency, second-pass frequency and missed next-speaker onsets with Auto Speak on and off. [Existing performance criteria](../docs/evaluation-and-acceptance.md) |
| Device experience | Repeat with both primary-language settings, rapid replies, manual pause/Stop, physical lock/unlock and playback from both orientations. Ready pairs start without a preparation sheet. Check the SwiftUI background-publication warning separately with a backtrace. |

**Delivery order.** First land the repeatable harness and baseline. Run the turn-finalization experiment and entity-check repairs in parallel. Integrate speaker resolution, playback and history after the audio ownership decision. Compare the resulting build with the baseline on the full matrix and with held-out human speech. The Hindi model trial can proceed independently and has its own enable/disable decision. The synthetic targets above are engineering milestones, separate from the repository’s human and release qualification criteria. [Qualification criteria](../evaluation/acceptance-criteria.json)
